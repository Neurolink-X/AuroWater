# AuroTap private file storage

## Design
- Supabase Storage bucket: `private-user-files` (private, 5 MiB object limit).
- Files are uploaded through authenticated Node.js API routes; the service-role key stays server-side.
- `public.user_files` stores ownership, category, object path, declared content type, byte size and review status. File bytes never go into Postgres.
- Upload validates allowed MIME types and file signatures. Paths are generated by the server and cannot be chosen by the browser.
- Downloads are short-lived (60-second) signed URLs and are checked against the authenticated owner or admin role.
- Sensitive identity/business/certificate files are admin-only until review.
- Upload and access actions are written to `audit_logs`; upload is rolled back if metadata or audit recording fails.

## API
- `POST /api/files/upload`: multipart fields `file` and `category`.
- `GET /api/files/:id`: returns a 60-second signed URL for the owner or an admin.

Allowed categories: `profile_photo`, `identity_document`, `business_document`, `skill_certificate`, `service_evidence`, `support_attachment`.

## Deployment
1. Apply `supabase/migrations/202610300002_private_file_storage.sql` to the correct Supabase project.
2. Deploy the application.
3. Smoke-test upload and signed download using a test account for each applicable role.
4. Verify the bucket is private and that anonymous/authenticated direct Storage access is denied.

## Operational limits
- 5 MiB per file; JPG, PNG, WebP and PDF only.
- Keep identity documents private; do not put their signed URLs in logs, analytics, emails or database rows.
- Add retention/deletion workflows only after legal and business retention requirements are defined.
